# P1 + Phase A 적용 안내

## 적용 순서

1. 기존 `01_nexus_schema.sql`이 적용된 프로젝트에서 `02_p1_phase_a.sql`을 SQL Editor로 실행한다. 새 파일만 실행한다. 운영 DB에는 이번 코드 작업에서 적용하지 않았다.
2. 앱 코드와 함께 배포한다. 배정 알림은 이제 DB 트리거에서 생성하므로 SQL을 먼저 적용한다. SQL 적용과 새 앱 전환 사이에는 구버전에서 배정 알림이 중복될 수 있어 짧은 전환 시간에 진행한다.
3. 서버 환경변수 `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL=deepseek-v4-pro`, `DEEPSEEK_BASE_URL=https://api.deepseek.com`을 확인한다. 로컬 모델 값은 설정 완료, 배포 환경은 별도다.
4. 관리자가 `/ai` → **운영 설정**에서 지침·일 호출 상한·월 토큰 예산을 저장한다. 회사 보안 정책 확인 후 외부 전송을 활성화한다. 기본값은 비활성, 숫자 가림 켜짐, 1인 10회/일, 팀 100만 토큰/월이다.
5. 대리 관리자를 기존 팀원 관리 화면에서 관리자 역할로 지정한다. 별도 계정/역할 코드는 필요 없다.

`public`, `auth`, `storage`는 이 SQL로 변경하지 않는다. `harim_nexus_private`는 노출하지 않는다. 테이블은 RLS+명시적 GRANT, 새 상태 전이 RPC는 service_role 전용이다. API는 매 요청마다 승인·활성 워크스페이스 구성원과 본인 소유 여부를 검사한다.

## 사용 흐름

- `/dashboard`: 지연 / 오늘 마감 / 이번 주 남은 내 업무, 미확인 배정 요청, 최근 알림, 주간보고 상태, AI 확인 건수. 기존 팀 대시보드는 `/team-dashboard`에 보존.
- `/weekly`: 월요일 기준 주차 선택 → 업무로 초안 생성 → 직접 편집 → 초안 저장 또는 제출. 관리자는 제출된 보고만 취합·인쇄 가능. 본인 확인된 주간보고 AI 요약도 인쇄에 포함.
- `/ai`: 업무 완료·지연 상태로 **저장**하거나 주간보고를 제출하면 검토 대기 기록을 DB 트랜잭션 안에서 만든다. 팀원이 **AI 질문 시작** → 최대 2라운드, 한 번에 1~3개 질문 → 답변 저장 → 요약 확인 → 공식 기록 확정. 충분한 기록은 질문 없이 요약할 수 있다. 높은 리스크는 확인 후 관리자 목록·알림에 반영.
- 단순히 시간이 지나 마감일을 넘겼다고 외부 API를 자동 호출하지 않는다. 새 지연 사유/업무 저장 시 검토가 준비된다. 무인 배치 호출·Cron은 추가하지 않았다.
- 완료·지연 업무의 확정 요약은 다음 주간보고 초안 생성/다시 적용 시 반영한다. 작성 중인 보고를 자동 덮어쓰지 않는다.
- AI는 상태/담당자/기한을 변경하지 않는다. 원본 수정 시 이전 검토는 `superseded` 처리하며, 처리 중 응답도 반영하지 않는다.
- 월마감 화면/실행 생성은 P2다. 이번 파일은 `source`, `source_ref`, `closing_run_id`와 월마감 완료 항목용 트리거 구분만 준비했다.

## 날짜·기록의 경계

- 업무 완료 전환 때 `completed_at`, 모든 수정 때 `updated_at`을 DB에서 기록한다. 완료 취소하면 완료일을 비운다.
- 기존 완료 업무의 실제 완료일은 알 수 없어 채우지 않는다. 완료 초안에도 포함하지 않는다.
- 주차·완료일·호출 예산 날짜는 `Asia/Seoul` 기준. 진행/지연/다음 주 마감은 현재 업무 상태를 사용하며 과거 상태 복원 기능은 아니다.
- 주간보고는 낙관적 잠금으로 다른 창의 수정을 덮어쓰지 않는다. 제출본을 초안으로 되돌리면 관리자 취합에서 제외된다.
- AI 답변은 외부 API 호출 전에 저장한다. 실패하면 `failed`와 오류를 남기며 저장된 대화로 재시도한다. 프로세스 중단 시 2분 지난 `processing`을 재시도할 수 있다.

## 비용·조회

- 홈 데이터 함수: 기존 인증/구성원 3회 + 내 업무·알림·보고 상태·AI 건수 4회. 일반 업무 허브의 파일/목표/자동화/감사 조회를 홈에서 하지 않는다. 공통 레이아웃·헤더 조회는 별도다.
- 주간보고: 주차 전체 업무 1회, 보고서 1회, 해당 업무 ID들의 확정 요약 1회. 팀 취합도 보고/구성원/요약을 표별 1회 조회한다. 날짜/보고서별 N회 조회 없음.
- 업무/주간보고 최대 500건 초과 시 불완전한 보고서를 만들지 않고 안내한다. 홈 업무는 100건+상한 안내, 알림 12건, AI 목록은 최근 100건이다.
- 본인 초안/AI 대화는 사용자마다 달라 공유 캐시 없이 `no-store` 사용. 새 화면 폴링 없음. 헤더 알림 1분 폴링은 비활성 탭에서 요청하지 않는다.
- 호출마다 DB 행 잠금으로 일 호출 수와 팀 월 예산을 확인한 뒤 예약한다. JSON 오류 1회 재시도도 별도 호출로 계산한다. 입력 UTF-8 byte 수 + 최대 출력 2048 + 여유 512 토큰을 보수적으로 예약하고 응답 usage가 있으면 실사용으로 정산한다. 응답을 확인할 수 없는 실패/중단은 예약량을 유지한다.
- `ai_reviews.input_tokens/output_tokens`는 성공적으로 기록한 usage 합계다. 정확한 예산 집계는 `ai_call_usage`의 실사용 또는 미확인 예약량을 사용한다.
- 실제 Vercel Functions Top Duration/Invocation 및 운영 트래픽 비용은 배포 후 확인해야 한다.

## 검증

- `npm test`: 주차/한국시간 완료일/미확인 완료일/지연/확정 요약/JSON 스키마/2라운드/숫자 가림/재시도/예산 실패 시 외부 전송 금지.
- `npm run build`: Next.js 14 빌드. dev/start 서버를 종료하고 실행한다.
- SQL: 운영과 분리된 PGlite에서 기존 bootstrap + 새 SQL 2회 실행, 트리거, RLS, 다른 회원의 검토 차단, 중복 claim, 상한 초과, 실패 시 답변 보존, 확인/원본 변경, 제출본 공개 범위, 비활성 회원/익명 차단 검증.

```powershell
npm.cmd install --prefix "$env:TEMP/nexus-phase-a-test" --no-audit --no-fund @electric-sql/pglite@0.3.14
$env:PGLITE_MODULE = "$env:TEMP/nexus-phase-a-test/node_modules/@electric-sql/pglite/dist/index.js"
node scripts/check-phase-a-db.mjs
```

PGlite는 Auth/Storage를 스텁으로 만들며 pgcrypto 확장 설치문만 제외한다(사용 함수 `gen_random_uuid`는 내장). 실제 Supabase Data API 적용 검증과 동일하지 않다.

- 브라우저: 실제 앱 + 가상 API 응답으로 홈/보고 작성·제출·취합/AI 질문·답변·확정/모바일 화면 검증. 운영 로그인 데이터로 검증한 것은 아니다.
- 실제 로컬 API 3개는 비로그인 401 확인.
- DeepSeek: `GET /models`에서 `deepseek-v4-pro` 확인. 가상 문서로 실제 JSON 응답 1회 검증. 실제 업무 데이터 전송 없음.
- 모델 매핑/JSON 출력 참고: [DeepSeek 모델 안내](https://api-docs.deepseek.com/quick_start/pricing/), [JSON 출력](https://api-docs.deepseek.com/guides/json_mode/).
